# Q80 打印機測試 App

`printer` 是互動式 OSAL 列印能力測試程式。啟動時不會出紙；只有點選列印項目才呼叫實體印表機。畫面顯示每項 API 的回傳值，`0` 代表成功。`X／Cancel` 或畫面 `EXIT TO MENU` 返回 MAINAPP。

| 按鈕 | 測試內容 |
| --- | --- |
| `CHECK` | `OsPrnOpen`、`OsPrnCheck`、`OsPrnGetDotLine`；不出紙 |
| `FONTS` | 列舉可用的 OSAL 字型；不出紙，完整名稱寫入 App 輸出 |
| `TEXT` | 英文、數字、符號的基本列印 |
| `SIZES` | 三種 OSAL 英文字級：12×24、16×32、24×48；再用 XUI 字型與 `OsPrnPutImage` 印同樣約 48 點高的 `SIZE 24x48`，以及 1、2 點細線，對照文字 API 與點陣 API |
| `CHINESE` | 用 XUI 的 `tm_font` 將中文字逐字分三行繪成 384×220 點陣圖，字高 64 點，再透過 `OsPrnPutImage` 列印 |
| `IMAGE` | 以手冊記載的逐行資料格式測試接近全紙寬的 384×240 點陣圖，含大字與方格 |
| `FEED` | 印一行標記並多走紙 96 點 |
| `DENSITY` | 使用 `OsPrnSetGray(4)` 測試手冊列出的最深濃度 |

每次列印先開啟印表機並檢查狀態，錯誤時不送列印內容；成功後以手冊列出的最高濃度等級 4 列印，最後關閉印表機。列印緩衝最多 2048 bytes，測試內容刻意保持短小。

```powershell
python -m q80 app build printer
python -m q80 app deploy printer
```

這台 Q80 的 `libosal.so` 中 `OsPrnOpen(0, NULL)` 會進入 `/dev/printer` 實體裝置路徑，因此在本機 `osal.h` 定義 `PRN_REAL=0`。手冊雖有 `PRN_BMP`，但這台庫包含多種非零模式且數值未確認，本 App 不測虛擬印表機。`OsPrnRawData` 沒有在這台庫匯出。

實機有 `/dev/printer`，權限為 `root:hwdev`、`660`；目前 MAINAPP 程序的補充群組包含 `hwdev`。這只能確認裝置節點可存取，不能代替實際列印測試。測試紙張輸出時應記錄文字是否完整、中文字型、圖片、濃度及走紙效果。

## Q80 實機結果

| 項目 | 回傳與紙張觀察 |
| --- | --- |
| `CHECK` | `OPEN 0 / CHECK 0` |
| `TEXT` | `RESULT 0`，原本濃度在舊紙上偏淡 |
| `DENSITY` | `RESULT 0`；等級 3 比預設深，等級 4 又更深 |
| `SIZES` | `RESULT 0`；三行依序變大 |
| `IMAGE` | `RESULT 0`；384×240 大圖完整出紙 |
| `CHINESE` | `RESULT 0`；64 點單字分三行清楚可讀 |
| `FEED` | `RESULT 0`；標記與額外走紙均正常 |
| `FONTS` | OSAL 僅列出 `paxfont.ttf`，不含本測試所需中文字 |

OSAL `OsPrnSetFont("tm_font")` 回傳 `-1003`，所以中文使用 XUI 字型先繪圖，再由 `OsPrnPutImage` 列印。28 點單行和 44 點兩行太擠或模糊；64 點單字分三行已確認清楚。紙張較舊，最終濃度與細線品質應在換新紙後再比較。尚未測缺紙／過熱錯誤、虛擬 BMP 印表機與手冊中的 `OsPrnRawData`（這台庫沒有匯出）。

## 第二台 Q80 的對照結果

第二台拆裝過主板。`TEXT` 及 `SIZES` 的 OSAL 文字很淡且缺筆；換用第一台可正常列印的紙卷後仍相同。`IMAGE` 的大面積圖形及 64 點中文字比較清楚，但近照可見黑塊、中文字也有白痕。新版 `SIZES` 在三行 OSAL 字後加印同樣約 48 點高的 XUI 點陣 `SIZE 24x48` 與 1、2 點細線：點陣字比 OSAL 字完整，但上半部仍缺筆，細線在固定位置中斷。畫面回報 `SIZES RESULT: 0`。第二台 `/usr/lib/libosal.so` 的 SHA-256 與專案先前擷取的參考庫相同，`paxfont.ttf` 的字型表可正常解析。

因此不能僅歸咎於 OSAL 字型或 API。需先檢查熱感頭與壓紙滾輪接觸、紙蓋扣合、印表機排線／接頭，再比較供電與印表機模組；目前沒有證據能直接判定 CPU 晶片受損。大黑塊可讀而細筆畫消失，符合接觸或加熱不足時細點先失效的現象；固定位置的線條缺口也可能指向特定熱感頭點位或訊號連接。這些是依紙張照片的推論，尚未拆機驗證。

熱感頭通常分別有邏輯供電與加熱供電。加熱供電偏低、接頭電阻偏高或列印瞬間壓降時，仍可能走紙並印出部分圖案；`OsPrnCheck() == 0` 不會量測紙上每個點的濃度。ROHM 的[熱感頭供電說明](https://techweb.rohm.com/product/printhead/printheads/20564/)指出加熱能量與供電、通電時間和瞬間電流有關，也要求均勻的滾輪壓力；[PAX Prolin API 手冊](https://manuals.plus/m/99959fafe713206af095195418306b793c64ebe967d1355cc636705bda7b248e)的 `OsPrnCheck` 只列出字型庫、忙碌、缺紙及過熱等狀態。這只能證明「供電異常仍可能部分印出」，不能從照片單獨確定第二台是供電問題。Q80 熱感頭實際型號與加熱電壓尚未查證，不應套用其他 384 點模組的針腳或電壓。

已將第一台同型號變壓器接至第二台，缺筆與細線斷點沒有改善。後續將兩台的印表機模組互換，故障跟隨原第二台的模組，裝上正常模組後列印恢復正常。因此問題已隔離至印表機模組；主板、CPU、外接變壓器與 App 列印 API 不是這次故障的原因。模組內究竟是熱感頭、排線／接點或壓紙機構，尚未進一步分解確認。
